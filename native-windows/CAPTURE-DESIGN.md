# 连续截图与集中整理（客户端 alpha 0.2）

目标：画面测试时，测试人员只负责操作被测软件和触发截图。每张截图立即加入当前用例，完成操作后集中补说明、排序、标注，再统一导出包含多张图片的 Excel。

## 工作流程

```text
选用例 / 步骤 → 开始连续截图
  → 快捷键框选，或重复截取上次区域
  → PNG + 采集时间 + 证据编号 + 步骤自动保存
  → 下一步骤 / 暂停 / 继续
  → 结束 → 缩略图列表 → 补说明 / 排序 / 标注 → 导出 Excel + 附件 + ZIP
```

每次截图自动保存项目数据；Excel 在最后统一生成。一个用例或步骤可以有多张图。图片独立保存，保留原分辨率和采集时间，Excel 根据图片顺序逐张排版。图片顺序独立于证据 ID，移动图片不改 ID。与表格、日志混排时，集中整理只调整图片所在的位置槽位，不移动其他证据。

第一版采用客户端内置截图，快捷键为 Ctrl+Alt+S（框选）和 Ctrl+Alt+R（上次区域）。如有冲突，可以换 Ctrl+Shift+F8 / F9 或点按钮。工具窗显示固定用例、当前步骤和保存数量；进入截图前冻结目的步骤，隐藏工具自身，避免截图过程中改动关联。

集中整理使用带缩略图的原生表格：逐图修改标题和说明；多选后追加统一说明或分配步骤；上下调整图片顺序；继续使用现有矩形、箭头、编号、文字、裁切工具。删除保留文件与恢复记录。整理说明未保存时提示保存或放弃，已经拍好的原图不受影响。

## 代码边界

| 部件 | 职责 |
| --- | --- |
| `ScreenCapture.cs` | Win32 全局快捷键、GDI+ 屏幕读取、原生框选窗；虚拟桌面坐标支持负起点 |
| `CaptureSessionForm.cs` | 固定用例、选择步骤、串行截图、暂停、保存结果、失败重试和回收 |
| `ImageReviewForm.cs` | 缩略图列表、批量说明 / 步骤、排序、标注和删除恢复 |
| `Captures.cs` | 待保存图片的持久化回收记录和一致性校验；不依赖 Windows |
| `Workspace.AddCapturedImage` | PNG 与 YAML 提交、revision 校验、重复重试识别 |
| `Workspace.SaveImageReview` | 只更新图片顺序、标题、说明、步骤，保留原图、哈希与采集信息 |

只改 `native-windows/`。仍使用 `image / table / text / file` 四种证据，不添加第五种证据、不更改项目 YAML 契约。无需浏览器、网络服务、截图软件或额外运行时安装。项目仍是文件夹。

## 保存和恢复

一次有效截图生成一个随机 token。先用临时文件 + Flush + rename 写入 `.capture-inbox/<token>.json`（含 PNG 字节及采集信息），再写 `evidence/<case>/capture-<token>.png`，最后原子替换用例 YAML。完成后移除回收记录。

- PNG 已写、YAML 未写：重试复用同名同哈希文件，重新提交关联。
- YAML 已写、回收记录未清理：根据原图文件识别已经完成，不再创建证据。后续标注使用的 `originalFile` 也可识别。
- 用户随后删除过该截图：检查已有删除记录，清理遗留回收记录时不自动把图片重新添加。仍可通过原有删除恢复操作找回。
- 外部修改用例：追加前读取最新用例，再校验 revision；保存期间的外部改动会拒绝覆盖。
- 保存失败：停止下一次截图，保留当前图片，可以重试或退避成项目外的 PNG。回收记录已落盘的图片可在重启后回收。
- 磁盘已满到连回收记录都无法写入：图片仅保留在本次进程内，界面阻止直接关闭，需先重试或写到其他位置。
- 同样的画面主动截图两次使用不同 token，两张都保留。仅对同一次保存的重试去重。

采集时间在读取屏幕时记录；恢复时不改成恢复时间。每次只处理一张待保存图片，工具窗显示保存中状态，避免快速连按同时写入同一个 YAML。框选取消不产生文件或证据。回收时原步骤被删除则拒绝追加，用户可导出 PNG 后重新分配。

回收目录含原始图片，属于项目本地数据；不会作为正常附件加入成果物，交付前应先处理未完成的截图。该机制不是跨主机共享文件夹并发控制；原有单编辑器限制仍适用。

## 验证与范围

测试覆盖相同图片的多次采集、保存失败回收、PNG / YAML 两个中断点、标注后重试、revision、步骤与 token 校验、图片篡改、批量排序 / 说明 / 非图片保留，以及 64 张图片的 Excel 输出和 Open XML 格式检查。它们验证数据流程，不模拟真实屏幕截图。

Windows Forms 真机、快捷键冲突、不同 DPI / 多屏、AWS RDP 和实际 Excel 渲染仍需按 `WINDOWS-ACCEPTANCE.md` 实测。RDP 中应在远端运行 evikit，目标是当前可见桌面；断开、锁定、最小化后的后台取证不在范围内。

暂不加入按鼠标点击自动抓图、定时录像、剪贴板后台自动收图、OCR、智能去重或多人协作。外部截图工具仍可手动粘贴；未来可加明确启用的剪贴板收图模式，但必须说明复制的任何图片都可能被收集。

Windows 官方 API 依据：[RegisterHotKey](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)、[Graphics.CopyFromScreen](https://learn.microsoft.com/en-us/dotnet/api/system.drawing.graphics.copyfromscreen)。
