# evikit Desktop for Windows

**独立した Windows Forms 版・alpha 0.6.1（DB データの自動整形・貼り付けプレビュー）。** ブラウザ版のソースは親ディレクトリに残しています。このディレクトリだけでビルドできます。旧 alpha 0.1 には連続撮影・大動画取込は含まれません。

Windows のネイティブコントロールと GDI+ を使用します。Chromium、Electron、WebView2、ブラウザ、Bun、Node.js、ローカル HTTP サーバーは使用しません。Excel の作成に Microsoft Excel のインストールも不要です。

## 配布版の起動

[リポジトリ内の release ディレクトリ](../release/) または [GitHub Releases](https://github.com/zhuyihenzheng/evikit/releases) から Windows 用 ZIP を取得できます。Git のみ外部接続できる環境では `git clone --depth 1 https://github.com/zhuyihenzheng/evikit.git` を実行してください。

1. `evikit-win-x64.zip` を Windows の書き込み可能な場所に展開します。
2. **フォルダー内の全ファイルを保持したまま `evikit.exe` をダブルクリック**します。
3. 「プロジェクトを開く…」で `project.yaml` のあるフォルダーを選択するか、「新規プロジェクト…」で作成します。
   同梱の `sample-project` は架空データのデモ用です。まずそのフォルダーを開くと、E01 のログイン前後の 2 画像・SQL 付き表・ログを試せます。
4. 用例・ステップを編集し、証拠を追加して「保存」。最後に「成果物を出力」を選択します。

配布フォルダーは .NET ランタイム同梱です。利用者による Bun / .NET / WebView2 の追加インストールは不要です。`evikit.exe` だけを取り出すと動作しません。対象は .NET 10 がサポートする Windows x64 環境です。Mac 上ではこの Windows アプリを起動できません。

会社のアプリ許可ポリシーは別途適用されます。未署名 alpha のため、許可リストや SmartScreen によって実行が制限される場合があります。ネットワークやアプリ制限を解除する機能はありません。

## 操作

- 左側：用例の検索、NG フィルター、用例追加。
- **用例名の変更**：用例を選択して「名前を変更」、一覧で F2、または用例をダブルクリック。決定すると現在の編集内容と一緒に保存し、一覧・見出しを更新します。「用例の情報 → 用例名」でも編集でき、こちらは Ctrl+S で保存します。変更後の Excel にも新しい名前を使用します。用例 ID（TC-001 等）を変更する操作ではありません。
- 用例の情報：タイトル・担当・日付・環境・前提条件・備考・判定。判定を空欄にするとステップから導出します。
- テストステップ：追加、編集、上下移動、削除。移動時は証拠との関連も更新します。ステップ削除時は関連証拠を「共通」に移します。
- テスト条件：各 Step の「テスト条件」列に入力。「テスト条件…」ボタンでは複数行のテストデータ・権限・初期状態を編集できます。用例全体の「前提条件」とは別です。保存・並べ替えで保持し、Excel は対応する Step の直下に出力します。
- 証拠：`image / table / text / file` の 4 種と 8 分類。分類は表示用です。
- 貼り付け：「＋ 証拠」の原文欄に Ctrl+V、メインの「貼り付け」、または「データを貼り付け」。列名 + データ行のある CSV / TSV を自動で表にし、右側にプレビューします。画像と表データが同時にある場合は表を優先。「画像を貼り付け」なら画像を指定できます。
- ファイル：証拠追加ダイアログから選択、またはメインウィンドウへドロップ。画像だけの複数ドロップは 1 件にまとめます。画像エビデンスを選択中ならそこへ追加し、それ以外は新規作成します。その他のファイルは 1 件ずつ情報を確認します。
- 画像：PNG / JPEG / GIF / BMP を読み込み、元ファイルのバイト列を保持。注釈保存時は別の PNG を生成。枠・矢印・番号・文字・切り抜き・取り消し。原図と注釈は別保存です。
- 表：UTF-8 CSV / TSV。先頭ゼロ、引用符内の改行を保持します。SQL は「出典 / SQL」に保存し、実行しません。
- テキスト：ログ、JSON、XML、SQL、コマンド結果など。実行機能はありません。
- 削除：証拠を一覧から除き、元ファイルと `.trash/native-*/evidence.json` を保持。「削除を復元」はこのセッションの直近の削除を復元します。
- 内蔵の「連続スクリーンショット」：撮影ごとに PNG・証拠情報を自動保存。同じエビデンスに画像を追加し、終了後に共通説明と各画像の説明・順序・注釈を整理できます。下記参照。
- `Ctrl+S`：保存。`Ctrl+Shift+V`：証拠貼り付け。注釈ウィンドウの `Ctrl+Z`：取り消し。

編集中は「未保存」が表示されます。用例・プロジェクトの切り替えと終了時に保存／破棄／キャンセルを選べます。証拠操作と出力の前には現在の草稿を保存します。

## 用例の削除と復元

- 用例を選択して左側の **「用例を削除」** を押します。用例一覧で Delete キーでも操作できます。確認画面には用例 ID・名前・ステップ数・証拠数を表示します。
- 確認後、未保存の編集がある場合は保存してから削除一覧へ移します。キャンセルは編集を保存せず、そのまま戻ります。
- 削除した用例は通常の一覧と以後の Excel / ZIP 出力に含まれません。別の用例・ステップ・証拠に影響しません。
- 左側の **「削除した用例」** を開き、対象を選んで **「選択した用例を復元」**。削除日時・名前・ステップ数・証拠数で確認できます。アプリを再起動しても一覧から復元できます。
- 復元すると元の ID・用例名・テスト条件・ステップ・複数画像・注釈・動画との関係が戻ります。同じ ID が既にある場合は上書きせず停止します。ファイルがなくなった場合や SHA-256 が一致しない場合も復元を停止します。

これは復元可能な削除です。YAML はプロジェクトの `.trash/native-case-<ID>/` に移し、画像・動画・撮影の回収記録は保持します。ディスク容量を解放する永久削除機能は含みません。復元関係を維持するため、削除済みの用例 ID は新規用例に再利用せず、自動採番もスキップします。旧版や外部エディターで同じ ID を作成しないでください。未完了の撮影は、用例を復元してから回収できます。

## 1 件のエビデンスに複数画像

- **新規**：「＋ 画像（複数）」で複数ファイルを選び、共通の見出しを入力。一覧は 1 行で、画像数を表示します。
- **追加**：画像エビデンスを選び「画像を追加・整理」。複数ファイル選択、ドロップ、貼り付けに対応。メイン画面の画像貼り付けも、画像エビデンスを選択中ならその行に追加します。
- **共通情報**：「共通情報を編集」で見出し・確認事項・Step・分類を設定。Step はエビデンス全体に適用されます。
- **画像ごとの編集**：見出し・説明は任意です。上下移動、複数選択で説明追記、個別注釈・原図へ戻す・取り出し・削除と復元ができます。最後の 1 枚を消す場合はメイン画面でエビデンス全体を削除してください。
- **既存行の統合**：同じ Step の画像エビデンスを Ctrl / Shift で複数選択し「選択を1件にまとめる」。一覧で最初の ID・共通情報を残し、他の画像・説明・原図をその中へ移します。異なる Step の統合は拒否します。
- **Excel**：エビデンス見出しは 1 回。内部に「画像 1/N、2/N…」、各画像・説明・ファイルリンクを整理した順番で配置します。

画像ファイルは結合・縮小せず独立して保存します。1 枚 25 MiB / 80 メガピクセルの上限です。複数ファイル取込は 1 枚ずつ保存し、途中で失敗した場合も保存済み分は残ります。

## 連続スクリーンショット

1. 用例を選び「連続スクリーンショット」を押します。画像エビデンスを選択中なら、その行に追加します。ステップ表から開始すると、その Step の新規エビデンスになります。
2. 保存先 Step とエビデンスを指定。新規は最初の撮影で作成し、以後は同じ行へ追加。「新しいエビデンス」で区切れます。「次の Step →」は新規の保存先へ切り替わります。
3. **`Ctrl+Alt+S`** で範囲をドラッグすると自動保存。**`Ctrl+Alt+R`** は同じ範囲を再撮影します。毎回の入力ダイアログは不要。Esc / 右クリックで範囲選択を取り消します。
4. 「終了して画像を整理」で、最後に保存したエビデンスの全画像を表示。「共通情報を編集」でまとめて説明し、必要な画像にだけ個別の説明や注釈を付けます。
5. 整理内容を保存し「成果物を出力」で Excel・添付・ZIP を生成します。

ショートカットは撮影ウィンドウを開いている間だけ登録します。一時停止・終了時に解除します。他のアプリと競合した場合は `Ctrl+Shift+F8`（範囲）/ `Ctrl+Shift+F9`（同じ範囲）へ変更するか、撮影ボタンを使えます。範囲を撮る際は evikit のウィンドウを隠します。

撮影ごとに原図 PNG と YAML を保存し、Excel の生成は最後に行います。同じ内容を意図して 2 回撮影しても 2 枚とも保持します。途中終了しても保存済みの画像は「画像を追加・整理」から編集できます。

保存前の画像は `.capture-inbox/` に回収記録を作ります。保存が失敗すると次の撮影を停止し、「保存を再試行」または「未保存画像を書き出す…」で対処できます。アプリが途中終了した場合は同じ用例で撮影ウィンドウを開き、「未完了の撮影を回収」を押します。**回収記録自体を書けなかった画像はメモリ上だけに残るため、アプリを終了せず再試行か別フォルダーへの書き出しを行ってください。** 回収中に元の Step やエビデンスが削除・変更されていた場合は追加を拒否するため、PNG を書き出して通常の証拠追加で登録し直します。

RDP では evikit をリモート Windows の中で実行し、表示中のリモート画面を撮影します。内蔵撮影はクリップボード転送に依存しません。RDP 最小化・切断・ロック中の撮影は対応対象外です。複数画面・DPI・RDP の実機検証は未完了です。画面構成が変わった場合は範囲を選び直してください。

今回の機能は evikit 内蔵撮影用です。Windows 標準の `Win+Shift+S` や他のツールの画像を自動収集する機能は含みません。外部ツールの画像は従来どおり貼り付けできます。

設計と保存・復旧の詳細：[CAPTURE-DESIGN.md](CAPTURE-DESIGN.md)。

## 動画の証拠

「＋ 動画」または通常のファイル追加 / ドロップで MP4、MOV、AVI、WMV、MKV、WebM、M4V を追加できます（拡張子による識別で、内容のデコード検査ではありません）。動画も `file` 証拠として扱い、同じ Step に複数の画像・動画・表を関連付けできます。ファイル添付の上限は **1 件 2 GiB**。画像は従来の 25 MiB 上限です。

動画を選択して「動画を開く」を押すと SHA-256 を検証し、指定したローカルプレーヤーを起動します。初回は会社で許可されたプレーヤーの `.exe` を選択してください。同じセッションでは選択を保持し、動画プレビューの「プレーヤーを変更」で変更できます。既定のファイル関連付けでブラウザを起動する方式は使いません。プレーヤーやコーデックは evikit に同梱していません。

「動画の確認画像」から、動画再生中に自分で撮影した PNG / JPEG 等を選択し、`00:35` などの確認位置を入力します。画像の出典に動画 ID・ファイル名・時間点が入り、元動画と同じ Step に追加されます。説明は後から編集・追記できます。フレームの自動抽出や自動カバー生成ではありません。

Excel は動画の名称・サイズ・説明・相対ファイルリンクと確認画像を表示します。動画本体は `files/` と ZIP に含みます。**ZIP を全部解凍してから report.xlsx を開き、files フォルダーとの位置関係を保ってください。** Excel のリンク操作は OS の関連付けを使うため、動画形式をローカルプレーヤーに関連付けてください。Excel セル内での再生、OLE 埋め込み、マクロ、内蔵録画、自動文字起こしは実装していません。

取込・取り出し・出力時はファイルを分割して読み込み、SHA-256 を計算します。ファイル添付を丸ごとメモリに展開しません。動画の ZIP 格納では再圧縮を省きます。ファイルが大きい場合は完了まで待機してください。保存・出力中の中止機能は現時点でありません。

## CSV から用例をまとめて作成

1. 左側の **「CSV から用例作成…」** →「テンプレートを保存…」。同梱の `case-template.csv` も使用できます。
2. Excel で編集し **CSV UTF-8** で保存します。1 行＝1 ステップです。
3. 「CSV / TSV を選択…」で読み込み、用例一覧・ステップのプレビュー・「用例の情報」を確認します。
4. **「プレビューの用例を作成」** でまとめて作成。完了後は通常どおり編集・証拠追加・出力ができます。

| テンプレートの列 | ルール |
| --- | --- |
| 用例ID | 各行に必須。同じ ID の行を 1 用例にまとめる |
| 用例名 | 用例ごとに最低 1 回入力。他の行は同じ値か空欄 |
| ステップ番号 | 正の整数、用例内で重複不可。空欄または列なしなら自動採番 |
| 操作 | 各行に必須 |
| テスト条件 | 任意。セル内改行可 |
| 期待結果 | 列は必須。値は空欄可、セル内改行可 |

例：`TC-CSV001` を 3 行書くと、1 用例・3 ステップになります。同じ ID の行が離れていてもまとめます。用例は最初の出現順、ステップは CSV の行順を保持します。自動番号は 1 から始め、手入力番号がある場合はそれまでの最大番号 + 1 です。ID の大文字・小文字を統一してください。

必須列は `用例ID / 用例名 / 操作 / 期待結果`。英語の `caseId / title / action / expected`、一般的な中国語列名にも対応します。英語の任意列は `stepNo / condition / actual / verdict / precondition / tester / date / env / caseNote`。日本語では `実際結果 / 判定 / 前提条件 / 担当者 / 実施日 / 環境 / 用例備考` も使えます。用例の共通情報は空欄を引き継ぎ、複数の非空値が異なるとエラーです。担当者・環境はプロジェクト設定、日付は取込日が既定です。Step の判定は空欄またはプロジェクト定義の値を使用してください。

UTF-8 CSV / TSV、2 MiB・10,000 ステップ以内。Shift-JIS は事前に UTF-8 に変換してください。列名の重複・未対応列・無効 ID・操作未入力・ステップ番号重複などを検出します。プレビューと全件チェックは用例を書き込みません。確定時も ID を再確認し、既存・削除済みの ID を上書きしません。

保存途中のディスク・権限エラーでは、作成済みの用例を保持して停止し、未作成分がプレビューに残ります。保存先の問題を解決後に再試行できます。バッチ全体のトランザクションではありません。強制終了後の再取込では、既に作成された用例の行を CSV から除いてください。CSV から画像等の証拠は登録しません。DB の結果は次節の「＋ 証拠」から追加します。

## DB の結果・CSV を表のエビデンスにする

1. DB ツールや Excel で **列名付きの結果データ**をコピーします。
2. 用例 →「証拠・プレビュー」→「＋ 証拠」。種類を **「自動（表 / テキスト）」** のまま、左の「原文 / 編集」に **Ctrl+V** で貼り付けます。「データを貼り付け」やメインの「貼り付け」も使えます。
3. 右側の **「表プレビュー」** と認識結果が更新されます。CSV（カンマ）/ TSV（タブ）とも、2 列以上・列名 + データ行がある整合した表を自動認識。手動で種類を変える必要はありません。元の文字列は左側に残り、編集すると再解析します。
4. 「ステップ」を指定し、「見出し」に確認対象、「出典 / SQL」に実行した SELECT 文、「確認事項」に確認した値を記入して「追加」。例：見出し「登録後の顧客レコード」、確認事項「customer_id=00012、status=ACTIVE を確認」。
5. 保存後も表としてプレビューでき、Excel に行列で出力されます。CSV 全文は添付にも入ります。

ファイルなら UTF-8 CSV / TSV を「ファイル選択…」またはメイン画面にドロップします。同じ追加前プレビューで確認できます。DB 接続や SQL 実行はしません。

```csv
customer_id,name,status
00012,テスト顧客,ACTIVE
```

- 先頭行を列名として使います。列名なしのコピーは先に列名を含めてコピーし直してください。列名を自動生成する機能はありません。
- 1 列だけの結果・列名だけでデータ 0 行の場合は **種類を `table`** に指定します。表にしたくないログ等は `text` を指定すると、その後の貼り付けも文字列のままです。「データを貼り付け」は自動モードへ戻します。
- 引用符・区切り・改行が不整合なら認識結果に理由を表示し、古いプレビューを消します。自動モードは原文をテキストとして保持。手動 `table` では修正するまで「追加」を無効にします。保存を押す時も最新の内容を解析します。
- Excel 等がクリップボードに画像と表データの両方を入れている場合、メインの「貼り付け」は表を優先します。画像として追加したい場合は追加画面の「画像を貼り付け」を使ってください。
- プレビューは先頭 500 データ行、保存・Excel は全行。2 MiB、列名 + 10,000 行、256 列以内。`00012`、空セル、引用符付きの改行、数式のような文字列を文字列のまま保ちます。並べ替え・行の削除・値の変換・自動判定はしません。
- Shift-JIS ファイルは UTF-8 に事前変換してください。空白で桁を揃えた出力、罫線付き端末出力、HTML だけのクリップボードは未対応です。CSV / TSV としてコピー・出力してください。

操作前後の比較は「変更前」「変更後」の 2 件を同じ Step に関連付けます。既に `text` として保存された証拠をこの更新で自動変換することはありません。必要なものを新たに表として追加し、確認してから旧証拠を整理してください。

## 出力する項目の選択

「成果物を出力」で出力設定が開きます。

- **現在の用例のみ**：画面で開いている用例 ID を明示します。用例選択中はこちらが初期選択です。Excel は「サマリ + この用例」の 2 シート、添付と ZIP もこの用例だけです。
- **全用例**：検索や「NG のみ」フィルターに関係なく、プロジェクトの活動中の全用例を出力します。用例未選択時はこちらを使用します。

出力範囲は毎回選び、以前の用例 ID を設定ファイルに記憶しません。出力先選択・完了メッセージにも対象範囲を表示します。指定用例がなくなった場合は停止し、全用例に切り替えて出力することはありません。manifest に対象 ID の一覧を記録します。

画像等の出力項目は初回すべてチェック済みです。

| 選択項目 | チェックを外すと |
| --- | --- |
| 画像 | 単画像・複数画像の証拠ブロックと画像添付を Excel / ZIP から除外 |
| 動画 | 動画の証拠ブロックと動画添付を除外 |
| その他のファイル添付 | 動画以外の `file` 証拠ブロックと添付を除外。`table` / `text` は保持 |
| 実施日・取得日時 | サマリの日付列、用例の日付、証拠・各画像の取得日時を非表示 |
| 担当者 / 環境 | サマリ・用例の対応する情報を非表示。担当者列も削除 |
| 前提条件・テスト条件 | 用例の前提条件と Step の条件行を非表示 |
| 備考・確認事項 | 用例・証拠・各画像の備考や確認事項を非表示 |
| 出典 / SQL | 証拠・各画像の出典情報を非表示 |

「出力先を選ぶ…」で保存先を指定して実行します。「全項目をオン」で既定に戻せます。設定はプロジェクト内の `.evikit/export-options.json` に記憶し、再起動後も使えます。設定・出力先のダイアログでキャンセルすると、草稿保存・設定保存・出力は実行しません。出力開始後にエラーになった場合は選択設定が残ります。

元の YAML・証拠は変更しません。用例名・操作・期待結果・実際結果・判定、表とログの本文は常に出力します。除外された証拠の ID は Step の証拠欄にも出さず、リンク切れを残しません。表示しない行・列に合わせてヘッダー固定位置を調整します。

日時等の選択はメタデータの表示設定です。本文・画像内の文字や日時、ファイル名、添付ファイル内部の情報は自動削除しません。出力フォルダー名の日時と manifest の生成日時は保持し、manifest に今回の出力設定を記録します。旧クライアントとブラウザ版はこの設定を適用しないため、選択出力は Desktop 0.5 以上で行ってください。

## 出力形式

選択した保存先に日時付きフォルダーを作成します。

```text
20260905-123456-xxxxxxxx/
  report.xlsx      # サマリ + 用例シート、画像、表、ログ抜粋
  files/          # 出力対象の証拠ファイル
  manifest.json   # ファイルごとのサイズと SHA-256
  delivery.zip    # 上記一式（ZIP 自身を除く）
```

Excel は全セルを文字列で保存し、数式として実行しません。基本列幅は 6 / 36 / 32 / 32 / 8 / 14、画像幅はプロジェクト設定、A4 横・横 1 ページに設定します。長いログは設定行数を抜粋し、全文は添付に残します。非常に長いセルは Excel の制限により出力を拒否します。

Excel からの添付リンクは相対パスです。`report.xlsx` と `files` を一緒に渡すか、ZIP 全体を展開してください。**デスクトップ版は HTML を出力しません。** 出力完了時は保存先をエクスプローラーで開けます。

## ブラウザ版との互換性

- 旧プロジェクトの `project.yaml`、`cases/*.yaml` / `*.yml`、`evidence/<caseId>/` はそのまま開けます。単画像は追加・統合・画像内編集まで従来の形式を保ちます。
- 複数画像は image エビデンスの `images` 配列に保存します。**この形式を含むプロジェクトは Desktop alpha 0.3 以降専用です。** ブラウザ版・旧クライアントでは開かないでください。本リポジトリのブラウザ版は読み込みを拒否し、画像の欠落や不完全な出力を防ぎます。
- 同じプロジェクトを両版で同時に開かないでください。共通の `.evikit.lock` で二重起動を拒否します。
- 外部で YAML が変更された場合、古い画面からの上書きを拒否します。草稿を控えてから再読込してください。
- 注釈は原図座標を保持するため、両版で再編集できます。ただし描画エンジンの違いで文字や矢印の見た目は完全一致しません。
- 将来の未知の YAML フィールドは、消して保存する代わりに読み込みエラーにします。
- Step の `condition` は任意フィールドです。未入力の旧プロジェクトはそのまま使えます。条件を入力したプロジェクトは alpha 0.2 以降のクライアントを使ってください。本リポジトリのブラウザ版データ読込・保存も condition を保持しますが、ブラウザの編集画面・出力にはまだ表示しません。旧版で保存し直さないでください。
- ブラウザ版の WebP 画像は現在のネイティブ画像処理では非対応です。PNG に変換して取り込んでください。非対応の証拠を黙って抜かして出力することはありません。
- ごみ箱の復元記録は版ごとに異なります。ブラウザ版で削除したものはブラウザ版から復元してください。

## 開発・ビルド

ビルド用 PC のみ .NET SDK 10.0.401（または同 feature band の新しいパッチ）が必要です。初回は Microsoft / NuGet への依存取得が発生します。利用時のアプリには更新確認・テレメトリー・HTTP クライアント・外部通信コードを実装していません。OS や企業の監視ソフトの通信は別です。

```powershell
cd native-windows
./build.ps1
```

PowerShell 実行ポリシーを変更せずに手動でビルドする場合：

```powershell
$env:DOTNET_CLI_TELEMETRY_OPTOUT = '1'
dotnet run --project tests/Evikit.Checks -c Release -- ../examples/reference
dotnet publish src/Evikit.Windows -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -p:DebugType=None -o artifacts/evikit-win-x64
```

`src/Evikit.Core` は OS 非依存なので Mac でもテストできます。Windows Forms のコンパイルも `EnableWindowsTargeting=true` で可能ですが、UI の実行試験には Windows が必要です。

## 現在の制限

ビルド・Core 104 項・64 枚の合成画像と 64 MiB の合成動画添付・Step 条件と複数画像の保存 / 並べ替え / 統合 / 個別注釈 / 削除復元 / 回収 / Excel 出力・Open XML 検証は確認済みです（詳細：`QA.md`）。Windows 実機での起動、連続撮影・ショートカット、RDP、プレーヤー連携、IME、日本語フォント、100/150/200% DPI、実 Excel の印刷・ハイパーリンクは現時点で未検証です。検証項目は `WINDOWS-ACCEPTANCE.md` を参照してください。

実行履歴（Runs）、マスク処理、DB / HTTP の自動採集、ログ整形、Word / PDF 出力、端末表の自動認識、Shift-JIS、署名・自動更新・インストーラーは実装していません。file 添付は 2 GiB、画像は 25 MiB / 80 メガピクセル、テキスト・表は 2 MiB、表はヘッダー + 10,000 行 / 256 列以内です。表プレビューは先頭 500 行、テキストプレビューは先頭 1,000 行まで。動画以外の画像・表・テキストと Excel の構造は出力中にメモリに保持するため、非常に多くの画像を持つプロジェクトは未検証です。大動画はデスクトップ版で処理してください。ブラウザ版の大動画処理は未検証です。
