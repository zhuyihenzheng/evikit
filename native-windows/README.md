# evikit Desktop for Windows

**独立した Windows Forms 版・alpha 0.2（連続スクリーンショット・動画添付）。** ブラウザ版のソースは親ディレクトリに残しています。このディレクトリだけでビルドできます。旧 alpha 0.1 には連続撮影・大動画取込は含まれません。

Windows のネイティブコントロールと GDI+ を使用します。Chromium、Electron、WebView2、ブラウザ、Bun、Node.js、ローカル HTTP サーバーは使用しません。Excel の作成に Microsoft Excel のインストールも不要です。

## 配布版の起動

[リポジトリ内の release ディレクトリ](../release/) または [GitHub Releases](https://github.com/zhuyihenzheng/evikit/releases) から Windows 用 ZIP を取得できます。Git のみ外部接続できる環境では `git clone --depth 1 https://github.com/zhuyihenzheng/evikit.git` を実行してください。

1. `evikit-win-x64.zip` を Windows の書き込み可能な場所に展開します。
2. **フォルダー内の全ファイルを保持したまま `evikit.exe` をダブルクリック**します。
3. 「プロジェクトを開く…」で `project.yaml` のあるフォルダーを選択するか、「新規プロジェクト…」で作成します。
   同梱の `sample-project` は架空データのデモ用です。まずそのフォルダーを開くと、画像・SQL 付き表・ログを試せます。
4. 用例・ステップを編集し、証拠を追加して「保存」。最後に「成果物を出力」を選択します。

配布フォルダーは .NET ランタイム同梱です。利用者による Bun / .NET / WebView2 の追加インストールは不要です。`evikit.exe` だけを取り出すと動作しません。対象は .NET 10 がサポートする Windows x64 環境です。Mac 上ではこの Windows アプリを起動できません。

会社のアプリ許可ポリシーは別途適用されます。未署名 alpha のため、許可リストや SmartScreen によって実行が制限される場合があります。ネットワークやアプリ制限を解除する機能はありません。

## 操作

- 左側：用例の検索、NG フィルター、用例追加。
- 用例の情報：タイトル・担当・日付・環境・前提条件・備考・判定。判定を空欄にするとステップから導出します。
- テストステップ：追加、編集、上下移動、削除。移動時は証拠との関連も更新します。ステップ削除時は関連証拠を「共通」に移します。
- テスト条件：各 Step の「テスト条件」列に入力。「テスト条件…」ボタンでは複数行のテストデータ・権限・初期状態を編集できます。用例全体の「前提条件」とは別です。保存・並べ替えで保持し、Excel は対応する Step の直下に出力します。
- 証拠：`image / table / text / file` の 4 種と 8 分類。分類は表示用です。
- 貼り付け：クリップボードの画像・テキスト。Excel のセルをコピーした TSV は表として扱います。テキスト中のカンマだけでは自動で表と判定しません。必要に応じて種類を `table` に設定してください。
- ファイル：証拠追加ダイアログから選択、またはメインウィンドウへドロップ。複数ファイルは 1 件ずつ情報を確認します。
- 画像：PNG / JPEG / GIF / BMP を読み込み、元ファイルのバイト列を保持。注釈保存時は別の PNG を生成。枠・矢印・番号・文字・切り抜き・取り消し。原図と注釈は別保存です。
- 表：UTF-8 CSV / TSV。先頭ゼロ、引用符内の改行を保持します。SQL は「出典 / SQL」に保存し、実行しません。
- テキスト：ログ、JSON、XML、SQL、コマンド結果など。実行機能はありません。
- 削除：証拠を一覧から除き、元ファイルと `.trash/native-*/evidence.json` を保持。「削除を復元」はこのセッションの直近の削除を復元します。
- 内蔵の「連続スクリーンショット」：撮影ごとに PNG・証拠情報を自動保存。終了後に複数画像の説明・順序・Step・注釈をまとめて整理できます。下記参照。
- `Ctrl+S`：保存。`Ctrl+Shift+V`：証拠貼り付け。注釈ウィンドウの `Ctrl+Z`：取り消し。

編集中は「未保存」が表示されます。用例・プロジェクトの切り替えと終了時に保存／破棄／キャンセルを選べます。証拠操作と出力の前には現在の草稿を保存します。

## 連続スクリーンショット

1. 用例を選び、「連続スクリーンショット」を押します。ステップ表の行を選択して開始すると、その Step が既定の保存先になります。それ以外は「共通」から選べます。
2. 小さい撮影ウィンドウで保存先 Step を指定します。用例とプロジェクトは撮影中に固定されます。「次の Step →」で次の操作へ進めます。
3. **`Ctrl+Alt+S`** で範囲をドラッグすると、その画像が自動で保存・採番されます。**`Ctrl+Alt+R`** は直前と同じ範囲を再撮影します。毎回の貼り付け・入力ダイアログは不要です。Esc / 右クリックは範囲選択の取消です。
4. 「終了して画像を整理」で、その用例の全画像を縮略図付き一覧に表示します。見出しと説明は表の中で編集できます。Ctrl / Shift で複数選択し、説明の一括追記や Step の一括変更ができます。上下移動、画像注釈、削除と復元にも対応します。
5. 整理内容を保存し、メイン画面の「成果物を出力」で Excel・添付・ZIP を一括生成します。同じ Step に何枚でも追加でき、Excel では各画像と説明を順番に配置します（ファイル・メモリ・Excel の上限内）。

ショートカットは撮影ウィンドウを開いている間だけ登録します。一時停止・終了時に解除します。他のアプリと競合した場合は `Ctrl+Shift+F8`（範囲）/ `Ctrl+Shift+F9`（同じ範囲）へ変更するか、撮影ボタンを使えます。範囲を撮る際は evikit のウィンドウを隠します。

撮影ごとに原図 PNG と YAML を保存し、Excel の生成は最後に行います。同じ内容を意図して 2 回撮影しても 2 枚とも保持します。途中終了しても保存済みの画像は「画像をまとめて整理」から編集できます。

保存前の画像は `.capture-inbox/` に回収記録を作ります。保存が失敗すると次の撮影を停止し、「保存を再試行」または「未保存画像を書き出す…」で対処できます。アプリが途中終了した場合は同じ用例で撮影ウィンドウを開き、「未完了の撮影を回収」を押します。**回収記録自体を書けなかった画像はメモリ上だけに残るため、アプリを終了せず再試行か別フォルダーへの書き出しを行ってください。** 回収中に元の Step が削除されていた場合は追加を拒否するため、PNG を書き出して通常の証拠追加で登録し直します。

RDP では evikit をリモート Windows の中で実行し、表示中のリモート画面を撮影します。内蔵撮影はクリップボード転送に依存しません。RDP 最小化・切断・ロック中の撮影は対応対象外です。複数画面・DPI・RDP の実機検証は未完了です。画面構成が変わった場合は範囲を選び直してください。

今回の機能は evikit 内蔵撮影用です。Windows 標準の `Win+Shift+S` や他のツールの画像を自動収集する機能は含みません。外部ツールの画像は従来どおり貼り付けできます。

設計と保存・復旧の詳細：[CAPTURE-DESIGN.md](CAPTURE-DESIGN.md)。

## 動画の証拠

「＋ 動画」または通常のファイル追加 / ドロップで MP4、MOV、AVI、WMV、MKV、WebM、M4V を追加できます（拡張子による識別で、内容のデコード検査ではありません）。動画も `file` 証拠として扱い、同じ Step に複数の画像・動画・表を関連付けできます。ファイル添付の上限は **1 件 2 GiB**。画像は従来の 25 MiB 上限です。

動画を選択して「動画を開く」を押すと SHA-256 を検証し、指定したローカルプレーヤーを起動します。初回は会社で許可されたプレーヤーの `.exe` を選択してください。同じセッションでは選択を保持し、動画プレビューの「プレーヤーを変更」で変更できます。既定のファイル関連付けでブラウザを起動する方式は使いません。プレーヤーやコーデックは evikit に同梱していません。

「動画の確認画像」から、動画再生中に自分で撮影した PNG / JPEG 等を選択し、`00:35` などの確認位置を入力します。画像の出典に動画 ID・ファイル名・時間点が入り、元動画と同じ Step に追加されます。説明は後から編集・追記できます。フレームの自動抽出や自動カバー生成ではありません。

Excel は動画の名称・サイズ・説明・相対ファイルリンクと確認画像を表示します。動画本体は `files/` と ZIP に含みます。**ZIP を全部解凍してから report.xlsx を開き、files フォルダーとの位置関係を保ってください。** Excel のリンク操作は OS の関連付けを使うため、動画形式をローカルプレーヤーに関連付けてください。Excel セル内での再生、OLE 埋め込み、マクロ、内蔵録画、自動文字起こしは実装していません。

取込・取り出し・出力時はファイルを分割して読み込み、SHA-256 を計算します。ファイル添付を丸ごとメモリに展開しません。動画の ZIP 格納では再圧縮を省きます。ファイルが大きい場合は完了まで待機してください。保存・出力中の中止機能は現時点でありません。

## 出力形式

選択した保存先に日時付きフォルダーを作成します。

```text
20260905-123456-xxxxxxxx/
  report.xlsx      # サマリ + 用例シート、画像、表、ログ抜粋
  files/          # 全証拠ファイル
  manifest.json   # ファイルごとのサイズと SHA-256
  delivery.zip    # 上記一式（ZIP 自身を除く）
```

Excel は全セルを文字列で保存し、数式として実行しません。基本列幅は 6 / 36 / 32 / 32 / 8 / 14、画像幅はプロジェクト設定、A4 横・横 1 ページに設定します。長いログは設定行数を抜粋し、全文は添付に残します。非常に長いセルは Excel の制限により出力を拒否します。

Excel からの添付リンクは相対パスです。`report.xlsx` と `files` を一緒に渡すか、ZIP 全体を展開してください。**デスクトップ版は HTML を出力しません。** 出力完了時は保存先をエクスプローラーで開けます。

## ブラウザ版との互換性

- `project.yaml`、`cases/*.yaml` / `*.yml`、`evidence/<caseId>/` を共用します。移行は不要です。
- 同じプロジェクトを両版で同時に開かないでください。共通の `.evikit.lock` で二重起動を拒否します。
- 外部で YAML が変更された場合、古い画面からの上書きを拒否します。草稿を控えてから再読込してください。
- 注釈は原図座標を保持するため、両版で再編集できます。ただし描画エンジンの違いで文字や矢印の見た目は完全一致しません。
- 将来の未知の YAML フィールドは、消して保存する代わりに読み込みエラーにします。
- Step の `condition` は任意フィールドです。未入力の旧プロジェクトはそのまま使えます。条件を入力したプロジェクトは alpha 0.2 以降のクライアントを使ってください。本リポジトリのブラウザ版データ読込・保存も condition を保持しますが、ブラウザの編集画面・出力にはまだ表示しません。旧版で保存し直さないでください。
- ブラウザ版の WebP 画像は現在のネイティブ画像処理では非対応です。PNG に変換して取り込んでください。非対応の証拠を黙って抜かして出力することはありません。
- ごみ箱の復元記録は版ごとに異なります。ブラウザ版で削除したものはブラウザ版から復元してください。

## 開発・ビルド

ビルド用 PC のみ .NET SDK 10.0.401（または同 feature band の新しいパッチ）が必要です。初回は Microsoft / NuGet への依存取得が発生します。利用時のアプリには更新確認・テレメトリー・HTTP クライアント・外部通信コードを実装していません。OS や企業の監視ソフトの通信は別です。

```powershell
cd native-windows
./build.ps1
```

PowerShell 実行ポリシーを変更せずに手動でビルドする場合：

```powershell
$env:DOTNET_CLI_TELEMETRY_OPTOUT = '1'
dotnet run --project tests/Evikit.Checks -c Release -- ../examples/reference
dotnet publish src/Evikit.Windows -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -p:DebugType=None -o artifacts/evikit-win-x64
```

`src/Evikit.Core` は OS 非依存なので Mac でもテストできます。Windows Forms のコンパイルも `EnableWindowsTargeting=true` で可能ですが、UI の実行試験には Windows が必要です。

## 現在の制限

ビルド・Core 48 項・64 枚の合成画像と 64 MiB の合成動画添付・Step 条件の保存 / 出力・Open XML / ExcelJS 回読は確認済みです（詳細：`QA.md`）。Windows 実機での起動、連続撮影・ショートカット、RDP、プレーヤー連携、IME、日本語フォント、100/150/200% DPI、実 Excel の印刷・ハイパーリンクは現時点で未検証です。検証項目は `WINDOWS-ACCEPTANCE.md` を参照してください。

用例の削除・復元一覧、実行履歴（Runs）、マスク処理、DB / HTTP の自動採集、ログ整形、Word / PDF 出力、端末表の自動認識、Shift-JIS、署名・自動更新・インストーラーは実装していません。file 添付は 2 GiB、画像は 25 MiB / 80 メガピクセル、テキスト・表は 2 MiB、表はヘッダー + 10,000 行 / 256 列以内です。表プレビューは先頭 500 行、テキストプレビューは先頭 1,000 行まで。動画以外の画像・表・テキストと Excel の構造は出力中にメモリに保持するため、非常に多くの画像を持つプロジェクトは未検証です。大動画はデスクトップ版で処理してください。ブラウザ版の大動画処理は未検証です。
